## 必须讲解、实现和观察的内容

1. 在真实 Redis 实现 SET NX PX + 随机 owner token + 比较删除 Lua，复现无 token DEL 删除新持有者锁。竞争失败、命令失败、响应未知分别处理，不能把任何失败都当未获得锁。

2. 用两个真实客户端和显式暂停，让 A 持有锁但工作停顿 → TTL 过期 → B 成功 → A 继续写；说明互斥租约不自动让旧工作停止，续租也不是业务幂等。下游需要 fencing/version 校验或数据库约束才能拒绝旧写。

3. 给 fencing 的单调 token 及下游拒旧契约，用真实 MySQL 独占行的版本条件更新持久保存最后接受 token，观察 stale-write 被拒绝；说明它依赖 token 权威和持久性，单 Redis 重启/复制问题不能靠示例推断安全。

4. 实现一种足够实用的固定窗口或滑动/令牌桶限流，以 Lua 原子更新必要计数和 TTL；讲清时钟、burst、拒绝和 Redis 不可用策略。按用户/接口键隔离；限流不能替代 worker/数据库池背压。

5. 验收锁竞争、超期、错误解锁、任务取消、重复释放及并发限额；不在共享 Redis 做宕机/全局配置故障。练习：证明 token DEL 必要；给旧 worker 写拒绝方案；解释为什么下单不能仅靠 Redis 锁防重复。Redlock 争议与多节点算法只作选学。
