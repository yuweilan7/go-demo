# M01：快速补齐业务代码语法、包与依赖管理

我是熟练的 Java 后端工程师，刚开始系统学习 Go，准备在 Shopee 阅读和维护复杂后端业务。我理解 Java 的线程池、异常、Spring、事务及常用中间件，但不能假定我懂 Go 的对应机制；已有示例出现过某语法也不等于我掌握了它。请以 Go 自身语义为主，用 Java 类比加速理解，并说清类比失效的地方。目标是让我能读真实代码、预测运行行为、定位错误和做有证据的小改动。

只完成本模块。先读适用的 AGENTS.md、根 README/go.mod、本模块已有交付及下方指定材料；files/ 是启发材料，必须纠正错误、版本差异和未经证实的绝对化结论。教学默认 Go 1.27；重新核对 go version、go env、模块 go/toolchain 指令和官方文档，区分语言保证、库契约及运行时实现。遇到公司旧版本代码，按其实际版本解释，不擅自升级。第三方依赖锁定实际可运行版本，不能凭记忆混用 API。

本模块交付中文 README.md、带详细中文注释的 Go 源码、可运行实验和必要的独立断言，STATUS.md 记录实际运行结果。复杂机制按“业务场景 → 最小规则 → 预期时间线 → 错误复现 → 修复对照 → 实际业务影响”递进，原理、反例、修复及完整解析直接放在文档和实验中。每课保留一个可在 10～20 分钟运行并讲清的核心实验，扩展分步展开。

所有手写 Go 教学代码都要采用 Python 学习项目那种详细、通俗的中文注释，包括实验入口、业务函数、并发协调、资源清理和关键断言。每个非平凡函数先说明在业务/实验中的职责、谁调用、参数从哪来、结果给谁以及拥有何种资源；在关键语句旁讲透变量是值副本还是共享对象、当前状态、为何选择该分支、在哪一行等待、错误/取消/panic 如何传播、defer 何时执行以及谁负责收尾。Go 小白不熟悉而本课正在使用的语法和 API 也要就地解释，如 := 的作用域、接收者、接口动态值、闭包捕获、channel 方向、返回值或驱动结果；不能只写“处理错误”“关闭连接”“启动协程”。简单且已讲清的赋值不重复凑字数，第三方和生成代码只解释相关入口与契约，不批量改注释。

README 从入口到真实副作用给出阅读顺序和带符号定位的完整调用链；并发/事务/消息实验按时间顺序列出“哪个参与者 → 当前函数/等待点 → 状态或资源变化 → 下一步为何发生”。对照实际日志、SQL/键值/消息和断言逐段解析正常、错误、取消与清理路径，说明不保证的调度顺序及 Java 类比的失效处。以上标准在本 prompt 内即可执行；仓库内的 [中文教学与源码注释规范](TEACHING_STYLE.md) 提供更具体的要求和注释示例，执行时一并读取。

## 必须讲解、实现和观察的内容

1. 不要重教 Java 基础；用订单状态校验函数串起 :=/=/var、零值、常量/iota、if 初始化语句、switch、for/range、多个返回值、可变参数和函数值。逐行解释 err 的作用域，复现内层 := 遮蔽外层 err 后错误被吞的业务后果。

2. 讲清同目录同包、多文件编译、大小写导出、包名与路径、init 及 import 副作用；修正按文件名猜 init 顺序的习惯，不把隐含初始化当依赖注入。演示 go run main.go 漏文件而 go run . 正常。

3. 用小的跨包服务说明返回值、多重赋值及 named result 的阅读方式；指针/接口只补签名阅读必需部分，把深层语义交给 M02/M04。数值类型、int 宽度、常量转换和溢出以能识别输入边界为限，不刷位运算题。

4. 通过 go list -m/go mod graph 读一次直接/间接依赖与版本选择；解释 replace 的本地作用及第三方消费者不会继承它。按实际依赖图和运行命令解释即可。

5. 用带完整解析的校验代码演示每个 err 实际绑定的变量、作用域错误及修正，展示单文件程序拆成正确两个包后的导入与调用关系。运行正确版本，保留错误版本的编译/行为证据；基础熟悉时可按文档和结果快速阅读。
