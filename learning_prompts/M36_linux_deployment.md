## 必须讲解、实现和观察的内容

1. 构建当前小服务的 Linux/amd64 或核对后的目标架构，解释 GOOS/GOARCH/CGO/动态链接/证书/时区资料和私有 module；保存版本、依赖及二进制 hash，交叉编译成功不等于目标机器可运行。

2. 在授权服务器的 go-demo 独立根和独立端口实际部署，选择 systemd 或独立容器之一，提供启动/停止/状态/日志命令、最低必要权限、配置私有路径与资源上限。不得切换 DeepHelp 的 active、systemd 单元或 volume。

3. 分别验证进程存活、readiness、实际 API 内容、依赖连接和在途工作；启动失败、端口冲突、配置错误不可用 health 伪装。无公网发布需求时用既有 SSH 方式看本地效果。

4. 真实发 SIGTERM 观察停止入口和 drain，设停机总预算，再比较 SIGKILL/进程崩溃的无清理路径；systemd restart policy 不等于 exactly-once。保存 pending/unknown 状态由业务恢复，不靠重启擦除故障。

5. 演示两个精确构建版本的部署与回退，说明 schema/配置兼容约束，不能回滚旧数据库覆盖新事实。练习：定位 Linux 启动失败；解释 signal 与 cancel 的关系；设计可检查的回退。验收实际服务器行为，Windows 模拟 stop 只作前置证据。
