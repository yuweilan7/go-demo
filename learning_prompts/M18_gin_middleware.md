## 必须讲解、实现和观察的内容

1. 把 M17 的小订单 API 接到真实 Gin，复用协议与断言，用 HandlerFunc/c.Next 前后输出展示洋葱顺序、路由组和错误映射。解释 Gin 的便利层究竟接管什么，事务和业务幂等仍由应用实现。

2. 复现 Abort 后当前 handler 仍继续执行、先 Bind 自动写出错误再重复 JSON、ShouldBind 与字段业务校验不同、body 被多次读取；用响应内容与副作用计数断言修复，不能只查状态码。

3. 区分 gin.Context 与 request.Context；框架对象可能复用，后台任务不得持有原 context/writer。Copy 也不自动赋予长期任务生命周期和可写响应权；提取不可变必要字段，后台任务显式 owner 与 budget。

4. 真实检查 Recovery 只能覆盖相应调用 goroutine 的边界，新 goroutine panic/外部提交不由它自动恢复。认证中间件、用户归属、可信代理/客户端 IP 和敏感日志处理给最小正确代码。

5. 沿一次请求定位源码里的 middleware 调度与路由调用，记录版本、文件和符号。验证鉴权拒绝、绑定失败、业务冲突、panic、超时和不发生额外写入；文档画出 Next 顺序，展示 Abort 漏 return 的修复与请求 ctx 传到依赖的完整路径。
