## 必须讲解、实现和观察的内容

1. 基于前置 API 建一个最小而真实的 handler → service/usecase → repository 组合，构造器显式注入；只划分确有职责的包，防循环 import，不造五层空接口。解释 Go 没有 Spring 默认容器替你管理生命周期。

2. 把环境变量/文件解析、必需项验证、默认值、启动、资源释放归入 composition root；配置不通过 context.Value 偷传。日志不输出 DSN/token；服务上线前暴露版本和有效的非敏感配置。

3. 给可执行的代码地图：main → 构造 → 路由注册 → 中间件 → 业务 → 仓储 → error 返回；每一跳链接真实文件/符号，列外部副作用和每个资源的 close owner。对 generated/wire 代码说明来源与重生成入口。

4. 用项目中的 service 构造演示 typed nil 注入、init 偷开连接、包全局可变 client、过早读取未启动资源；通过构造断言/生命周期实验修复。DI 工具只做阅读比较，未需要时不安装多套。

5. 交付综合项目可采用的最小接口与请求状态契约，但代码仍位于本模块目录，后续模块不来并行改这里。练习：追踪一条请求；把隐式全局依赖改为显式构造；定位配置来自哪个层。单模块清晰胜过框架名词堆叠。
