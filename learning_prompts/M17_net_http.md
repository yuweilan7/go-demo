## 必须讲解、实现和观察的内容

1. 用真实本机 server/client 解释 Handler、Request、ResponseWriter、Client、Transport；对比 Servlet/RestTemplate/HTTP client 的责任，但 Go 请求函数同步阻塞当前 goroutine，不需要 async 关键字。

2. 客户端复用 Client/Transport，明确 body 消费与关闭、最大响应大小、非 2xx/JSON/业务错误的层次。读取到 EOF 对连接复用通常重要，但不能为复用无界 drain 攻击者响应；超限则按明确策略结束。

3. 分别观察 connect/TLS/response header/body 与整体 ctx/Client.Timeout；展示请求取消后服务端继续处理的证据。连接池限制和空闲连接回收不是业务并发限流，不把全局 client 每请求 CloseIdleConnections 当正常清理。

4. 服务端设置实际合适的 header/body/idle/写预算与大小限制，区分普通 JSON 和长流；WriteHeader/Write 后不能重新选择状态码。不要在 handler 返回后继续使用 writer。只初步处理可信代理、认证和输入边界。

5. 用慢响应、坏 JSON、过大响应、早断开和重复请求验证关键路径；重试只留规则，不自动重试下单。直接解析 response body 泄漏的修复、timeout 所处阶段，以及 HTTP 200 但业务未提交的真实对照。
