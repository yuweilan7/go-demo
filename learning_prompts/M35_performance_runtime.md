## 必须讲解、实现和观察的内容

1. 把旧教程的源码版本写出来，先讲 goroutine 调度、stack growth、allocation/GC 与工程现象的关系，不背 span size class 或某个调度常数。GOMAXPROCS、CPU quota 与实际可并行容量按当前运行环境核验。

2. 用当前 testing benchmark API（核验 B.Loop 等）做稳定、有可解释 work 的基准，报告 ns/op/B/op/allocs/op、样本及构建环境；避免优化掉工作、以单次 wall time 判断性能或拿 -race 数字当性能结果。

3. 真实用 -gcflags 对目标包看 escape/inlining，结合 heap/CPU profile 定位 slice 保留、临时字符串、interface/闭包分配。纠正所有 interface 转换一定逃逸、新建指针一定堆分配和指针总更快等绝对说法。

4. 对一个有证据的热点做单一改动，并核对行为不变量与前后重复测量；sync.Pool 不能作为资源池或可靠缓存，缓冲区复用需清零/所有权证明。无证据不做 unsafe 零拷贝和全局对象复用。

5. 用有界实验解释 GOGC/GOMEMLIMIT 的成本和软限制、Go 堆与进程 RSS 不同，关注非 Go/网络/数据库资源；不能为挤进共享服务器而随意调 DeepHelp 配额。练习：审查一个失真 benchmark；定位分配；决定优化是否值得。验收只针对当前平台与样本，不推广成永远更快。
