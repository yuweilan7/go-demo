## 必须讲解、实现和观察的内容

1. 讲清 (value,error) 契约，包括某些 I/O 可以同时返回有效字节与错误，不能把 err != nil 时所有结果无用变成普遍规则。用业务 NotFound、Conflict、依赖失败、Canceled 区分调用方应该做什么。

2. 复现同文案不同错误实例、%v 丢错误链、直接断言看不到 wrapper、typed nil 和错误类型 T/*T 不一致；用 %w、Is、As 和当前版本可用的 AsType 修复。新旧 API 对照要实际编译。

3. 用 Unwrap 和 errors.Join 说明主错误与清理错误如何都被保留；不要让 Close 失败覆盖业务失败，也不能吞掉写出/Flush/Commit 错误。解释错误链不自动带调用栈，栈由边界日志或具体类型提供。

4. 给错误分类到 HTTP/RPC/消息处理结果的最小映射；只在拥有上下文的边界记录必要日志，避免逐层 log-and-return。error 可被包装，但取消/超时类别仍需保留。

5. 练习：从错误链找数据库原因；修复丢链与 typed nil；为可重试/不可重试/结果未知三类设计断言。不能凭错误字符串决定支付或下单重试，完整请求重试交 M33。
