## 必须讲解、实现和观察的内容

1. 用创建订单与局部更新 DTO 展示 struct tag、导出字段、omitempty、缺失/null/0/空集合、指针可选字段、自定义解码及重复名字/未知字段/尾随数据问题；反序列化成功不代表业务参数有效。

2. 默认把既有 encoding/json 作为读业务代码的主线，再对当前 Go 1.27 JSON v2 做小的真实对照；核对其正式 API、默认行为和兼容选项，不能沿用旧实验包/tag 教法，也不能静默更换整个项目的协议。

3. 复现解到 map[string]any 后大整数被 float64 处理、金额相加精度与截断问题；在本课契约中用带币种的 int64 最小单位，检查输入、溢出、舍入和汇率边界。若使用 decimal，说明其数据库/JSON 契约和版本。

4. 讲清 time.Time/time.Duration、UTC/业务时区、字符串解析、单调时钟与墙钟、序列化后单调部分消失；用过期订单展示时区、单位和 Unix 毫秒/秒混用。不要仅改变显示格式冒充修复。

5. 交付未来综合项目可参考的字段契约：request_id/order_id/user_id/SKU/quantity/currency/amount_minor 与 UTC 时间，并保持契约版本。练习：区分三种 PATCH 输入；修复大 ID 和金额；验证跨时区到期判断。
