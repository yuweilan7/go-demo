## 必须讲解、实现和观察的内容

1. 在独占 SKU 上使用两个独立数据库连接和明确屏障重现 check-then-update 超卖，再比较带 stock>=qty 条件的原子 UPDATE、SELECT FOR UPDATE 与 version CAS；依据业务不变量决定方案，而不是都加分布式锁。

2. 逐步实验 Read Committed/Repeatable Read 的普通快照读与锁定读，记录实际隔离级别、索引和执行计划；gap/next-key lock 的出现有版本、隔离与索引条件，不能把 PostgreSQL 或 JPA 经验直接移植。

3. 相反顺序锁两条记录，稳定触发死锁；采集真实错误码/锁等待信息、回滚被选中的事务，再按可幂等业务重试整个事务。死锁与 lock timeout 不等价，statement 失败是否结束整事务需按服务配置核实，应用应明确 rollback。

4. 解释持事务调用慢 RPC/Redis 的锁占用、长事务保留历史版本、缺索引扩大锁范围；应用 mutex 不跨实例。按权限读取必要诊断，不为学习开启全局 general log 或修改共享服务器全局参数。

5. 验收并发库存永不为负、成功数量守恒、唯一订单、死锁后可恢复和等待预算。练习：预测两个事务读值；按一致顺序锁；解释重试范围和外部副作用风险。只能声明当前单机/窗口的证据，不声称无限规模安全。
