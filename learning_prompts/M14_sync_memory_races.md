## 必须讲解、实现和观察的内容

1. 先用库存检查再扣减说明临界区和不变量；各自使用 atomic 的 Load/Store 仍可能业务超卖。说明 Go happens-before 与 Java JMM 的共同目标和具体原语边界，没有锁不能凭 goroutine 执行先后推断可见性。

2. 复现普通 map 并发访问、同对象不同锁、复制含锁 struct、值接收者、锁重入与 RWMutex 升级死锁；坏 fatal 场景隔离到子进程，用 -race/vet 和独立库存断言定位。

3. 使用 Mutex/RWMutex、typed atomic/CAS 与不可变快照解决适用问题；持锁访问网络 I/O 的等待放大、锁顺序和共享 slice backing array 都必须被解释。不要把 atomic.Value 容器安全误读为内部 map 可随意改。

4. sync.Map 只教适用访问模式、LoadOrStore/CompareAndSwap 与 Range 非整体快照边界，避免把多个单命令组合当原子事务。旧 readOnly/dirty 源码是版本相关实现，当前本机使用 HashTrieMap，核验源码后再谈。

5. Once 的 panic/失败初始化与重试、Pool 的回收和对象重置风险只掌握日常必要行为。练习：区分 race detector 报告与超卖；修复复制锁；设计一次原子状态转移。验收无 race 的修复及业务不变量同时满足。
