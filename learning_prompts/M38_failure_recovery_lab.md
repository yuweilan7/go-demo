## 必须讲解、实现和观察的内容

1. 先冻结业务不变量与故障矩阵：库存非负/守恒、幂等请求一订单、一 event_id 一业务效果、成功终态必须有事实、结果未知必须可查。每项给触发位置、观察证据、恢复动作和允许的暂态。

2. 以真实进程/网络代理/本课专用连接制造 ctx timeout、服务端已接受但响应丢失、Tx 中 panic/提前返回、DB pool 饱和、依赖变慢；反例定位到函数/状态，不能以单元 mock 返回错误代替通信故障。

3. 真实停止/重启本课独立 Kafka/消费者/relay 或终止本课应用，覆盖 DB commit 后 publish 前、publish 后 outbox 更新前、consumer DB commit 后 offset 前。共享 Redis/PG 不宕机，Redis不可用用本课代理/连接隔离。

4. 演练 duplicate、同聚合乱序、rebalance、Redis lease 过期旧 owner、缓存旧读回填和 SIGTERM 在途；没有实现某个选学机制就标不适用并说明，不强行声称测了。故障数量以独立风险为依据，不凑矩阵。

5. 每次恢复后查数据库/outbox/inbox/offset 和 API 实际内容，记录唯一效果与 pending/unknown；只恢复本课自己的资源，不回滚陈旧数据、不删状态掩盖失败。练习：盲排一个故障；审错恢复方案；证明一个看似成功日志为何是假阳性。最终保留必要证据并确认全部实验进程/代理退出。
