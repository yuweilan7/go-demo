## 必须讲解、实现和观察的内容

1. 先独立讲当前 Timer/Ticker/AfterFunc：Stop/Reset 的返回语义、不关闭 C、不等待已开始回调；按 Go 1.27 核验旧 asynctimerchan 兼容开关已移除，不能复制旧 stop-drain-reset 写法并宣称普遍必要。

2. ticker 是触发源，不是可靠任务队列，处理慢可丢 tick；实现每轮耗时任务的允许重叠/禁止重叠/跳过策略，防止 time.After 在高频循环中无证据使用、default 忙转和定时任务 panic 静默丢失。

3. 复用 M15 的任务协议设计 shutdown：停止入口 → 停止生产者 → 排空或明确放弃队列 → 等待 worker → 关闭客户端。cancel 仅通知，真正退出须 join；timeout 到来要报告在途/未知状态。

4. 用 signal.NotifyContext 或可控 stop 入口模拟服务生命周期；清理用独立短预算，不从已取消 request ctx 直接派生一个立即失败的清理 ctx。关闭顺序由依赖关系决定，不能边处理数据库任务边关闭 DB。

5. 验收任务执行中停机、空闲停机、队列满、回调已启动、重复 shutdown 和超预算。练习：定位一个停不掉的 ticker worker；为在途订单选 drain 策略；说明 kill/崩溃为何不保证 defer。真实 Linux 信号由 M36 再证实。
