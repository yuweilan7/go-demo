## 必须讲解、实现和观察的内容

1. 真实连接现有 Redis，使用当前锁定版 go-redis/v9，私有凭据按已有路径加载且不输出。每个实验用 golearn:m25:<run>: 前缀，设置合理 TTL，只清理自己创建的精确键；禁止 FLUSHDB 和 broad pattern 删除。

2. 讲 Client/连接池、ctx、命令 result/error、redis.Nil 缓存 miss、timeout/auth/type 错误的区别。核对实际客户端如何处理 ctx 与 socket timeout，不能假定一个 WithTimeout 一定中断所有连接阶段。

3. 在真实服务上验证 GET/SET/HASH/INCR/EXPIRE、无 TTL 与剩余 TTL、过期及单位误用；SET 后忘设 TTL、读改写丢并发更新、JSON 解码失败不等同 miss，用业务断言修复。

4. pipeline 是批量发命令，不自动提供业务原子性；TxPipeline/MULTI/EXEC 与 SQL rollback 不等价；Lua 可原子组合 Redis 命令，但脚本错误和执行时长有边界。用一个命令运行失败的实验证明不能期待 SQL 式全回滚。

5. 验收读写/过期、miss、类型错误、取消/池等待及资源归属；连接关闭由课的生命周期 owner 完成，不能每次请求 Close client。在实验中展示 INCR+EXPIRE 的竞争与修复，区分三种错误，解释 Redis 有数据为何不足以证明订单已提交。
