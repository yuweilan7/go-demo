# 中文教学与源码注释规范

适用于这套课程的全部模块，以及后续对已生成课程的解释补充。学习者是熟练 Java 后端工程师、Go 初学者：Java 的线程、异常、事务、容器和中间件经验可以用于类比，Go 的语法、对象关系、框架机制与 API 契约仍需要从当前代码讲清。

每份模块 prompt 已包含下面的核心要求，可独立复制执行。本文件放在仓库里作为共同标准，执行者读取后将要求落实到自己的模块目录。可以按需使用 `go-learning-by-running` 的教学方法，课程执行不依赖额外安装 skill。

## 交付形式与阅读过程

每课交付中文 README、带详细中文注释的手写 Go 源码、可运行实验、必要的独立断言，以及真实 STATUS。原理、错误反例、修复版本和完整解析直接交付在同一课程中。

读课路径是：具体业务场景 → 最小 Go 规则 → 入口与调用关系 → 预期状态/时间线 → 运行实验 → 对照日志与副作用 → 理解错误原因与修复。反例和修复使用同一套合成业务数据和清楚的实验编号，避免为展示一个新概念再造一套复杂业务。

README 说明哪些现在必须理解、哪些遇到相关源码时再查。低价值细节按阅读需要点到即可；涉及事务、并发、资源、取消、缓存和消息正确性的机制应完整展开。

## 源码旁要解释到什么程度

所有手写教学代码都在范围内：实验入口、业务函数、repository/client 包装、并发协调、故障触发、资源清理和关键测试断言。每个非平凡函数先用中文说清职责，再在关键语句或代码段旁解释行为。初学者应能沿注释读懂代码，而不必反复回 README 猜一个变量和函数的角色。

根据当前函数涉及的机制，覆盖这些问题：

- 谁调用这个函数，它在业务或实验的哪一层；参数来自哪里、返回值交给谁。
- 变量代表哪项业务事实或协调状态；是值副本、指针别名、共享对象，还是一次请求专属数据。
- 这一行为什么执行，这个条件为何成立；成功、失败、空结果、取消和重试会走哪个分支。
- 调用是同步完成还是启动了另一个 goroutine；当前具体等待哪个 channel、锁、连接、请求或任务。
- 谁拥有 goroutine、连接、Rows、Tx、timer 等资源；谁发停止通知、谁等待退出、谁做最后清理。
- error 从哪一层产生，是否包装并保留原因；panic 在哪个 goroutine 展开、recover 位于哪里、返回到哪一层。
- defer 在何时注册、当时捕获什么值、退出时读取什么值；会不会因为作用域遮蔽或提前求值误判结果。
- SQL/Redis/MQ/RPC 的实际副作用何时发生，调用返回是否足以证明业务完成；响应丢失时有哪些已知事实和未知结果。
- 这段写法避免了什么具体错误，修复改变了哪个状态或协议边界；哪项日志/断言能证明这一点。

本课正在使用、Go 小白尚不熟悉的语法和 API 也要就地解释。例如 `:=` 的声明范围、具名返回、方法接收者、接口动态类型/值、闭包读取时机、slice 的共享底层数组、channel 方向、`select` 的分支条件、驱动结果的含义。语法解释必须连到当前变量和当前行为，不能只留下术语。

复杂机制可以逐语句或连续代码段解释，注释写完整的中文句子。简单且已经解释过的赋值、打印与重复样板不机械复述；第三方源码和生成代码只在 README 定位相关入口、版本与契约。修改代码时同步核对注释，删掉失效解释。

## 注释的具体写法

“启动协程”“处理错误”“提交事务”“关闭连接”不足以说明发生了什么。要写出本段代码涉及的对象、时机和后果，例如：

| 代码位置 | 应解释的具体内容 |
| --- | --- |
| `go worker(...)` | 入口创建独立 goroutine；owner 保存停止方式和完成信号；入口返回不会自动等待或取消它 |
| `tx.ExecContext(...)` | 这里使用当前 Tx 占用的连接，SQL 属于同一事务；改为外层 DB 调用会绕开这个事务 |
| `defer tx.Rollback()` | 注册本 Tx 的退出清理；提交前退出会尝试回滚；已提交后不能撤销事实；Rollback 的错误如何处理由实际实现说明 |
| `cancel()` | 发出取消通知；工作函数何时观察 ctx、I/O 何时返回、owner 何时等待任务退出仍需分别说明 |
| `CommitMessages(...)` 或 `Ack(...)` | 客户端向 broker 确认哪个进度；本地业务提交必须在哪个阶段；进程在两者之间中断会怎样 |
| 实验中的 `assert`/条件断言 | 它证明哪个业务不变量或先后关系，什么故障会让它失败；证明范围是否覆盖实库与 broker |

下面这段展示注释颗粒度和边界说明，属于写法示例。实际课程必须提供完整可运行文件、导入、实验入口及验证记录。

```go
// sendResult 由 worker 调用，把本次计算的文本结果交给收集者。
// results 由调用方传入并负责关闭；本函数只发送，不拥有 channel 的生命周期。
// ctx 沿用本次任务的取消范围，让收集者提前退出时 worker 有机会结束等待。
func sendResult(ctx context.Context, results chan<- string, result string) error {
    // chan<- 表示这里仅能发送，不能从 results 读取。
    // 没有接收者或缓冲已满时，发送暂时不能进行；select 会等待可进行的分支。
    // 不直接写 results <- result，是为了在等待期间也能观察 ctx 的取消通知。
    select {
    case results <- result:
        // 这里只证明结果已被 channel 接受：可能交给了接收者，也可能进入缓冲。
        // 它不能证明收集者已完成数据库写入；那个事实应由后续业务确认来表示。
        return nil
    case <-ctx.Done():
        // Done 关闭使这条接收可立即进行；Err 给出 Canceled 或 DeadlineExceeded。
        // 将错误交回 worker 的 owner，由 owner 等待退出并决定整批任务的结果。
        return ctx.Err()
    }
}
```

这段代码还需要在文档里说明两个边界：调用方必须保证发送期间没人关闭 `results`，否则向已关闭 channel 发送仍会 panic；发送与取消同时就绪时，`select` 可能选中发送，不能承诺“取消通知之后绝不会发送”。这些是实际行为，应和注释、实验结果一起讲清。

## README 的调用链与时间线

每个实验给出精确工作目录、入口命令、阅读顺序、关键函数/类型/变量名、输入、预期观察点和实际结果。多文件实验要指出每个文件负责什么。框架课沿真实版本源码定位一次完整调用，不凭函数命名补出不存在的链路。

串行路径先说明 caller → callee → 返回/错误 → 上层处理。并发路径为每个 goroutine 指定 owner、当前函数、实际等待点、停止条件和被谁等待完成。资源路径说明创建 → 使用 → 失败/取消 → 清理 → 最终状态。

事务、缓存或消息实验可以使用下面这种时间线；按实际参与者和日志填写，不把示意顺序当成所有运行的保证：

| 步骤 | 参与者与当前函数 | 状态/资源变化 | 下一步与证明点 |
| --- | --- | --- | --- |
| 1 | 请求入口调用 usecase | 建立请求 ctx，校验输入与幂等键 | 标明哪个函数继续执行 |
| 2 | usecase 开始 Tx | 绑定本事务的数据库连接 | 后续 SQL 明确使用该 Tx |
| 3 | Tx 内执行业务与 outbox SQL | 未提交写入仍在本事务内 | 故障分支怎样返回及清理 |
| 4 | 调用 Commit | 记录返回结果与可确认的持久事实 | 通信中断后按实际错误分类查询未知结果 |
| 5 | relay 发布事件 | broker 确认与 outbox 状态分别记录 | 展开发布成功但状态未更新的窗口 |
| 6 | 消费者处理并确认进度 | 业务效果与 ack/offset 分阶段发生 | 对照幂等记录和恢复后结果 |

运行日志逐段对应到函数和关键语句，解释每条事件的含义。明确“通知”“观察通知”“退出”“清理完毕”“owner 等待完成”之间的区别。对并发只断言有机制保证的先后关系；偶然的 worker 顺序和精确耗时只能作为本次观察。

Java 类比用来帮助理解当前代码，并紧接着说明 Go 的差异。例如 `defer` 需要解释函数返回时机与参数捕获，goroutine 需要解释创建、阻塞和拥有者，`context` 需要解释协作取消及副作用边界。

## 实验与交付核对

正常版本、危险版本和修复版本都给直接解析，错误点标在实际代码旁，证明结果来自运行。错误程序放明确的故障入口或有界子进程；核心正常入口能完成，并发协调使用屏障/可观察状态。

必要断言验证独立的业务事实和协议边界，例如库存守恒、回滚后表内容、资源最终释放、broker 重投后业务效果唯一。实库、中间件与故障实验采用真实服务；辅助单测的替身注明其范围。命令、日志与 STATUS 如实记录版本、命名空间、结果、未验证范围和清理。

交付前沿入口完整读一遍源码和 README：读者能否知道变量的角色、每个调用的去向、等待对象、错误来源、返回位置和资源结局；每项关键说明是否能与运行结果核对。缺少解释就补在相应代码旁，缺少运行证据就将相应实验标为未完成。每课的完成状态依据文档、代码和实验的交付事实。
