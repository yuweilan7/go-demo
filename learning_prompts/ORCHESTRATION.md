## 委派与模型

各层模块数依次为 19、7、5、5、1、1、1，每个模块一个子 agent，使用 `gpt-6.1-sol`、`xhigh`。本机会话配置 `service_tier = "priority"`，子 agent 使用工具所支持的 priority 服务；不以 prompt 声称已修改实际模型。记录实际派发参数和工具返回。

每个子 agent 使用独立、已登记的 managed worktree。主工作目录中尚未提交的调度文档从绝对路径只读；用户新复制的 `files/` 也从主目录只读，不复制/提交整批原材料。执行者只写分配给它的 `lessons/mXX_slug/`，命令显式指定自己的 worktree/模块目录。

子 agent 不创建新的 agent，不切换主目录分支，不提交、不推送、不改共享文件。所有修改在所属模块目录内，课程具备独立 go.mod、详细 README/注释、可运行实验、必要断言和 STATUS。工作区私有文件放已忽略的 `.local/` 或 `.secrets/`。实验有时间和并发上限；共用 Git/Go 缓存不意味着共享业务数据。

## 严格整层屏障

1. 按 `modules.json.topological_waves` 选择当前层。只有前一层已全部 ACCEPTED 且整层提交完成，才可创建该层执行者。第 0 层的 19 个模块全部委派，不自动从编号相邻添加依赖。
2. 每次派发前持久记录 CREATING 和目标路径，派发后立即保存 agent 名称。结果不明确时核对 agent、worktree 和已产物后再决定，禁止盲重试创建。
3. agent 仍在运行则保持 RUNNING，不重复发送任务。agent 自报完成后进入 REVIEW，不因自然结束或 PASS 字样直接验收。
4. 主 agent 阅读实际源码、README、STATUS 和实验记录，核对 prompt 的全部内容、Go/依赖版本、关键行为与失败路径、注释深度、真实副作用和资源清理。运行必要的独立复验，记录命令与真实结果。未覆盖内容、无法运行或证据不足时标 NEEDS_FIX，向原 agent 明确返工。
5. 主 agent 验收后标 ACCEPTED，从活动集合移除，保留结果、证据和 agent 历史。当前层还有未验收模块时不跨层。
6. 整层 ACCEPTED 后，把各 worktree 已验收的模块文件汇总到主目录。排除私有配置、凭据、临时报告、编译产物和其他模块文件；核对主目录中的路径、导入、前置契约与文件差异，完成必要组合验证。
7. 确认层内没有遗留失败或待补关键实验后，主 agent 只暂存本层授权模块及必要导航/调度文档，用中文说明做一次整层提交；写入提交 SHA 与验收记录。用户原有未跟踪 `files/` 不纳入提交。
8. 持久更新当前层后再派下一层。已验收模块不重复重跑全部实验；新增集成、依赖变化或具体疑点只复验受影响部分。

每个模块的 STATUS 记录本模块实际执行事实，主 agent 的验收保存在 `.local/course-orchestrator/acceptance/`。层记录另保存实际汇总和提交结果；“课程文档存在”与“代码完成”和“真实实验通过”分别核对。

## 基础设施与故障边界

M00 只建立入口与协调约定并进行有界只读验证。MySQL、RabbitMQ、Kafka 到首次需要的相应模块时，由一个持锁安装者在授权学习服务器安装独立实例；其他模块复用实际端点。共享 DeepHelp 服务、活动数据、恢复卷和发布状态不作为实验对象。

秘密通过已忽略的私有文件加载，不输出/提交正文；每个实验使用专属端口、数据库/表、Redis 前缀、vhost、topic 和 group。远端安装或需要运行课程代码时按 INFRASTRUCTURE 执行。实库、真实 MQ、真实故障验收不能由 mock、编译成功或健康检查替代。关键连接/容量问题保留实际诊断并修复，当前层仍有缺口就保持屏障。

## 五分钟监测与恢复

主 agent 活跃时可以继续派发、核对和修复，不必空等下次定时器。heartbeat 作为持久跟进，在同一会话读状态和 `collaboration.list_agents`；只在需要结果或失败细节时读取 agent 更新和模块报告。没有变化时安静结束，只在层推进、关键失败、需要用户输入或最终完成时通知。

状态更新写临时文件后原子替换，并维护 revision。创建与提交结果不明确时先核对 Git、worktree 和 agent；不回滚用户文件，不中断其他项目任务，不重复安装服务或重新派发仍在运行的 agent。

若 agent 已无法恢复且模块尚未验收，先确认没有活跃写入者，在同一模块 worktree 接管或替换执行者，保留原诊断与已完成产物。委派关联始终从状态恢复，禁止将缺失的 agent 历史误认为模块成功。
